# Design: Astro + Preact Machine Visualization System

**Date:** 2025-01-16
**Status:** Ready for Implementation
**Author:** Design Session with Claude Code

## Executive Summary

Replace the homemade static site generator (SSG) with an Astro + Preact architecture to visualize 109+ XState machines. This addresses performance, developer experience, feature extensibility, and scalability issues with the current implementation.

**Current State:**
- 2 monolithic HTML files (271KB + 1.1MB)
- String concatenation HTML generation
- Basic Mermaid diagrams
- No code splitting or lazy loading
- Difficult to add interactive features

**Target State:**
- 134 optimized static pages (1 home + 24 categories + 109 machines)
- Component-based architecture with Preact
- Interactive Stately Inspector visualizations
- Automatic code splitting by category
- <1s page loads with lazy loading

## Goals

1. **Performance** - Reduce initial load from 1.4MB to ~200KB, <1s time to interactive
2. **Developer Experience** - Component-based development vs string concatenation
3. **Features** - Add search, filtering, interactive diagrams with minimal effort
4. **Scalability** - Handle growth beyond 109 machines without performance degradation

## Architecture

### Technology Stack

| Layer | Technology | Rationale |
|-------|-----------|-----------|
| SSG Framework | Astro 4.x | Best-in-class SSG with Islands architecture, automatic code splitting |
| UI Components | Preact 10.x | Lightweight React alternative, perfect for islands |
| State Visualization | @stately/inspect | Purpose-built for XState, interactive diagrams |
| State Machines | XState 5.x | Existing dependency, no changes needed |
| Styling | CSS + Existing design system | Reuse current gradient/color scheme |
| Deployment | GitHub Pages | Existing infrastructure |

### Hybrid Architecture: Astro Islands

```
┌─────────────────────────────────────────┐
│         Static HTML (Astro)             │
│  ┌────────────────────────────────┐    │
│  │  Header, Navigation, Layout     │    │
│  └────────────────────────────────┘    │
│                                         │
│  ┌──────────────┐  ┌──────────────┐   │
│  │ Preact Island│  │ Preact Island│   │
│  │ SearchFilter │  │   Stately    │   │
│  │ (client:load)│  │  Inspector   │   │
│  │              │  │(client:visible)   │
│  └──────────────┘  └──────────────┘   │
│                                         │
│  ┌────────────────────────────────┐    │
│  │  Static Content (badges, etc)  │    │
│  └────────────────────────────────┘    │
└─────────────────────────────────────────┘
```

**Key Principle:** Only hydrate interactive components, keep everything else as static HTML.

### 3. Machine Loader (machine-loader.ts)

**Purpose:** Dynamically import actual XState machine files

**Implementation:**
```typescript
export async function loadMachine(machineId: string): Promise<AnyStateMachine> {
  // Use Vite's glob import
  const machines = import.meta.glob('/src/workflows/**/*Machine.ts');

  // Find matching file
  const machinePath = Object.keys(machines).find(path =>
    path.includes(`${machineId}Machine.ts`)
  );

  // Dynamic import
  const module = await machines[machinePath]();

  // Extract exported machine
  return findMachineExport(module);
}
```

**Benefits:**
- Type-safe imports
- Automatic code splitting
- Works with existing machine file structure

## Code Splitting Strategy

### Manual Chunks Configuration

```javascript
// astro.config.mjs
manualChunks(id) {
  // Split by machine category
  if (id.includes('/workflows/')) {
    const match = id.match(/\/workflows\/([^/]+)\//);
    if (match) return `machines-${match[1]}`;
    return 'machines-general';
  }

  // Separate chunks for large libraries
  if (id.includes('@stately/inspect')) return 'stately-inspector';
  if (id.includes('xstate')) return 'xstate-core';
}
```

**Result:**
```
_astro/
├── xstate-core.[hash].js              # ~50KB gzip (shared)
├── stately-inspector.[hash].js        # ~80KB gzip (shared)
├── machines-agriculture.[hash].js     # ~20KB (on-demand)
├── machines-commerce.[hash].js        # ~15KB (on-demand)
├── machines-health.[hash].js          # ~25KB (on-demand)
└── ... (24 category chunks)
```
