# 📥 Lineage Generation System - Required Inputs

## Overview

The lineage generation system requires several inputs to build the complete traceability chain from **Legal Sources → Features → Rules → Workflows**. This document describes all required inputs and their dependencies.

## 🔄 Execution Flow & Dependencies

```
Source Files (Source of Truth)
    ↓
Metadata Generation Scripts (Parse & Extract)
    ↓
Aggregated Metadata JSON Files (Intermediate)
    ↓
Lineage Generation Script (Build Relationships)
    ↓
Individual JSON Files with Lineage (Output)
```

## 📋 Required Inputs

### 1. Source Files (Primary Inputs)

These are the actual source files in your codebase that contain the business logic:

#### 1.1 Gherkin Feature Files
**Location**: `features/**/*.feature`

**Example**: `features/benefits/ris.feature`
```gherkin
# @specification-version:2024.1.0
# @effective-date:2024-01-01
# @legal-basis:Loi du 26 mai 2002 concernant le droit à l'intégration sociale
# @legal-url:https://www.ejustice.just.fgov.be/cgi_loi/change_lg.pl?language=fr&la=F&cn=2002052647&table_name=loi
# @implemented-by:src/rules/risRules.ts

Fonctionnalité: Revenu d'Intégration Sociale (RIS)
  ...
```

**Required Metadata**:
- `@specification-version`: Version of the specification
- `@legal-basis`: Legal basis text
- `@legal-url`: Official legal source URL
- `@implemented-by`: Path to implementing rules file (optional but recommended)

**How to Generate**: These files are created manually by developers when adding new features.

#### 1.2 Rules Files
**Location**: `src/rules/*.ts`

**Example**: `src/rules/risRules.ts`
```typescript
export const RIS_RULES_METADATA = {
  implementsSpecification: '2024.1.0',
  lastSyncedWith: 'features/benefits/ris.feature',
  generatedFrom: 'features/benefits/ris.feature@2024.1.0',
};
```

**Required Metadata**:
- `implementsSpecification`: Must match feature `@specification-version`
- `lastSyncedWith`: Path to feature file (for explicit linking)
- `generatedFrom`: Full reference to feature (optional)

**How to Generate**: Created manually by developers when implementing features.

#### 1.3 Workflow/Machine Files
**Location**: `src/workflows/**/*Machine.ts`

**Example**: `src/workflows/social/risApplicationMachine.ts`
```typescript
export const risApplicationMachine = createMachine({
  id: 'risApplication',
  initial: 'idle',
  // ...
});
```

**Required**:
- Machine `id` should match benefit type or reference rules
- Machine name/category should align with rules/features

**How to Generate**: Created manually by developers when creating workflows.

#### 1.4 Legal Metadata Registry
**Location**: `src/domain/legalMetadata.ts`

**Example**:
```typescript
export const MACHINES_LEGAL_METADATA: Record<string, MachineLegalMetadata> = {
  risApplication: {
    currentVersion: {
      sources: [{
        authority: 'SPF Intégration Sociale',
        title: 'Loi du 26 mai 2002',
        officialUrl: 'https://...',
      }],
    },
  },
};
```

**Required Functions**:
- `getMachineLegalMetadata(machineId: string)`: Get legal metadata for a machine
- `getMachineSources(machineId: string)`: Get legal sources for a machine

**How to Generate**: Maintained manually or via `scripts/generateLegalSources.ts`.

### 2. Intermediate Metadata Files (Generated Prerequisites)

These files must be generated **before** running the lineage generator:

#### 2.1 Features Metadata
**Location**: `docs-astro/public/features-metadata.json`

**Generated by**: `npm run features:metadata`

**Structure**:
```json
{
  "generated": "2025-01-18T10:00:00.000Z",
  "totalFeatures": 178,
  "features": [
    {
      "id": "benefits-ris",
      "name": "Revenu d'Intégration Sociale (RIS)",
      "category": "benefits",
      "metadata": {
        "specificationVersion": "2024.1.0",
        "legalBasis": "Loi du 26 mai 2002...",
        "legalUrl": "https://...",
        "implementedBy": "src/rules/risRules.ts"
      },
      "scenarios": [...]
    }

```

**Command**: 
```bash
npm run features:metadata
# or
node scripts/generate-features-metadata-standalone.js
```

**Generated by**: `npm run rules:metadata`

**Location**: `scripts/lineage/lineage.config.json` (optional)

**Structure**:

```json
    "fallbackEnabled": true
  },
  "performance": {
    "batchSize": 100,
    "parallelWorkers": 4,
    "cacheEnabled": true,
    "cacheTTL": 3600
  },
  "validation": {
    "strictMode": false,
    "requireExplicitLinks": false

    "featuresDir": "features",
    "rulesDir": "rules",
    "workflowsDir": "machines"
  }

```

**Default**: Uses hardcoded defaults if file doesn't exist.

## 🚀 Execution Order

### Full Build (Recommended)

```bash
# Step 1: Generate all metadata files (in parallel if possible)
npm run docs:metadata      # Generates machines-metadata.json
npm run rules:metadata     # Generates rules-metadata.json
npm run features:metadata  # Generates features-metadata.json

# Step 2: Generate lineage (requires all metadata files)
npm run docs:individual    # Generates individual files with lineage
```

**Or use the combined command**:
```bash
npm run docs:build
# This runs all steps in sequence:
# 1. docs:metadata
# 2. rules:metadata
# 3. features:metadata
# 4. docs:individual
# 5. docs:generate
```

### Incremental Build (After Changes)

If you only changed one feature:

```bash
# Regenerate only the changed feature's metadata
npm run features:metadata

# Regenerate lineage (will detect changes)
npm run docs:individual
```

## 📦 Dependencies

### Runtime Dependencies

The lineage generator requires:

1. **Node.js**: v16+ (for async/await, fs.promises)
2. **TypeScript**: v4.5+ (for type checking)
3. **ts-node**: For running TypeScript directly

### NPM Packages

From `package.json`:
```json
{
  "dependencies": {
    // Core dependencies (if using new architecture)
    "winston": "^3.x",           // Logging (optional)
    "prom-client": "^14.x"      // Metrics (optional)
  },
  "devDependencies": {
    "typescript": "^5.x",
    "ts-node": "^10.x",
    "@types/node": "^18.x"
  }
}
```

### Source Code Dependencies

The lineage generator imports from:

1. **`src/domain/legalMetadata.ts`**:
   - `getMachineLegalMetadata()`
   - `getMachineSources()`

2. **`src/utils/machineMetadataHelper.ts`**:
   - `getDataFreshnessBadge()`

**Note**: These are imported dynamically using `require()` to work with `ts-node`.

## 🔍 Input Validation

The system checks for required inputs and provides helpful error messages:

### Missing Metadata Files

If `features-metadata.json` is missing:
```
⚠️  features-metadata.json not found. Run npm run features:metadata first.
```

### Missing Source Files

If a feature references a rule file that doesn't exist:
```
⚠️  Rule file not found: src/rules/risRules.ts
   Referenced by: features/benefits/ris.feature
```

### Missing Legal Metadata

If legal metadata is not available:
```
⚠️  Legal metadata not available: Cannot access legalMetadata.ts
   This is normal if legalMetadata.ts is not accessible
```

Before running lineage generation, verify:

- [ ] All source files exist:
  - [ ] Feature files in `features/**/*.feature`
  - [ ] Rule files in `src/rules/*.ts`

- [ ] Metadata files are generated:
  - [ ] `docs-astro/public/features-metadata.json` exists
  - [ ] `docs-astro/public/rules-metadata.json` exists
  - [ ] `docs-astro/public/machines-metadata.json` exists
- [ ] Legal metadata is accessible:
  - [ ] `src/domain/legalMetadata.ts` exists and exports required functions
- [ ] Dependencies are installed:
  - [ ] `npm install` has been run
  - [ ] TypeScript and ts-node are available

## 🐛 Troubleshooting

### Error: "Cannot find module 'src/domain/legalMetadata'"

**Solution**: Ensure you're running from project root and `ts-node` can resolve TypeScript files.

### Error: "Metadata file not found"

**Solution**: Run the prerequisite metadata generation scripts first.

### Error: "No implementing rules found"

**Solution**: 
- Check that `@implemented-by` in feature matches actual rule file
- Verify rule file has `lastSyncedWith` metadata
- Check benefit type matching if using inferred discovery

### Error: "Version mismatch detected"

**Solution**: Ensure feature `@specification-version` matches rule `implementsSpecification`.

---

**Summary**: The lineage generator requires **source files** (features, rules, workflows) and **generated metadata files** (JSON) as inputs. Run metadata generation scripts first, then run lineage generation.
